orders

Purchase orders placed by customers in the supply chain.

Layer: Core Type: Entity Rows: 15,000 Related: customer, lineitem

Schema

ColumnTypeDescription
o_orderkeyINTEGERPrimary key — unique order identifier
o_custkeyINTEGERFK → customer.c_custkey
o_orderstatusVARCHAROrder status: O (open), F (fulfilled), P (partial)
o_totalpriceDECIMALTotal order value
o_orderdateDATEDate the order was placed
o_orderpriorityVARCHARPriority level (1-URGENT, 2-HIGH, 3-MEDIUM, 4-NOT SPECIFIED, 5-LOW)
o_clerkVARCHARClerk who processed the order
o_shippriorityINTEGERShipping priority flag
o_commentVARCHAROptional remarks

Business rules

  • o_orderkey is the primary key (unique, not null)
  • o_custkey must reference a valid customer.c_custkey
  • o_orderstatus is derived: F if all lineitems shipped, O if none shipped, P if partially shipped
  • o_totalprice equals the sum of lineitem extended prices for the order
  • Referenced by lineitem.l_orderkey
  • Each order has 1–7 line items

Example queries

Orders by status

SELECT o_orderstatus, COUNT(*) AS order_count, 
       SUM(o_totalprice) AS total_value
FROM orders
GROUP BY o_orderstatus;

Top customers by order value

SELECT c.c_name, COUNT(o.o_orderkey) AS num_orders,
       SUM(o.o_totalprice) AS total_spent
FROM orders o
JOIN customer c ON c.c_custkey = o.o_custkey
GROUP BY c.c_name
ORDER BY total_spent DESC
LIMIT 10;
