Pipelines

ETL jobs, schedules, and data flow.

Overview

Pipelines move data between layers, apply transformations, and materialize output tables on a defined schedule. All pipelines read from the TPC-H source tables and produce aggregated or enriched outputs consumed by dashboards, metrics, and the Lighthouse LLM context layer.

Pipeline Registry

Pipeline Schedule Input Output Description
daily-revenue Daily @ 02:00 UTC lineitem, orders daily_revenue_agg Aggregates line-item revenue by date, segment, and region. Powers the revenue dashboard and trend metrics.
customer-segmentation Daily @ 03:00 UTC customer, orders customer_segments Assigns tier labels (high-value, medium, low) based on order frequency and total spend over a rolling 90-day window.
supplier-performance Weekly (Monday 04:00 UTC) lineitem, supplier, partsupp supplier_scorecards Computes on-time delivery rate, average discount given, and part diversity per supplier. Used for procurement risk analysis.
order-fulfillment Hourly orders fulfillment_metrics Calculates real-time fill rate, average time-to-ship, and open order counts. Feeds operational alerting.

Pipeline Architecture

All pipelines follow a consistent pattern:

  1. Extract — Read from DuckDB source tables (TPC-H schema)
  2. Transform — Apply SQL-based aggregation and business logic
  3. Load — Write results to materialized output tables
  4. Notify — Update the wiki metadata and trigger downstream consumers

Pipelines are idempotent: re-running a pipeline for the same date window overwrites (not appends) the output partition. This ensures consistency after retries or backfills.
