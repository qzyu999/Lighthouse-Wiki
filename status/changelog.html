Changelog

Recent changes to the TPC-H data platform.

Latest Changes

This page tracks recent modifications to schemas, pipelines, metrics, and infrastructure. Entries are listed in reverse chronological order.

2024

2024-07-15 — Added lineitem.l_shipmode index

Created a non-unique index on l_shipmode to accelerate ship-mode-based filtering queries (TPC-H Q12, Q19). Query performance improved ~3x for mode-specific aggregations on the SF=0.01 dataset.

Scope: lineitem table, DuckDB storage layer

2024-07-01 — Migrated from CSV to DuckDB native storage

Replaced the flat CSV file ingest with DuckDB's native columnar format. All 8 TPC-H tables now stored as .duckdb database file. Benefits: 10x faster cold-start queries, column pruning, predicate pushdown, and native DECIMAL support.

Scope: All tables, storage infrastructure

2024-06-20 — Added partsupp table

Introduced the partsupp bridge table with composite PK (ps_partkey, ps_suppkey). Previously, part-supplier relationships were embedded as denormalized columns in lineitem. This normalization enables proper supply cost analysis and supplier diversity metrics.

Scope: New table, lineitem FK relationships updated

2024-06-01 — Normalized nation/region from customer table

Extracted nation and region into separate dimension tables. Customer and supplier tables now reference n_nationkey via foreign key instead of storing nation/region names as strings. Reduces storage and enables geographic hierarchy queries.

Scope: customer, supplier, nation (new), region (new)

2024-05-15 — Initial TPC-H data generation (SF=0.01)

Generated the initial TPC-H dataset at Scale Factor 0.01 using dbgen. Loaded all 8 tables: region, nation, supplier, customer, part, partsupp, orders, lineitem. Total ~60K line items, ~15K orders, suitable for development and testing.

Scope: Full schema, initial load

2024-05-10 — Wiki infrastructure created

Set up the Lighthouse Wiki with catalog, metrics, pipelines, semantics, and status sections. Established the wiki.css design system and page templates for documenting the data platform.

Scope: Documentation infrastructure

Change Format

Entries follow the pattern: date, affected component, change type (added, modified, deprecated, removed), and a brief description of impact. Each entry includes a scope indicator showing which tables or systems were affected.
