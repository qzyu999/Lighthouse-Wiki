Migrations

Schema changes, column renames, and deprecations.

Migration History

All schema migrations for the TPC-H dataset are tracked below. Each migration has a version number, description, impact assessment, and current status. Migrations follow semantic versioning: major = breaking changes, minor = additive changes, patch = non-breaking fixes.

Version Date Change Impact Status
v2.0 2024-08-01 (planned) Split customer address into structured fields: c_address → c_street, c_city, c_postal_code. Deprecate the original c_address column after 30-day dual-write period. Breaking — All queries referencing c_address must be updated. Affects customer-segmentation pipeline and geographic dashboards. 📋 Planned
v1.2 2024-06-25 Added composite primary key enforcement on lineitem(l_orderkey, l_linenumber) and partsupp(ps_partkey, ps_suppkey). Rejects duplicate inserts at the storage layer. Non-breaking — Enforces existing uniqueness constraint. No query changes needed. Duplicate rows (if any) were deduplicated before enforcement. ✅ Complete
v1.1 2024-06-10 Changed l_extendedprice from INTEGER to DECIMAL(15,2). Also applied to o_totalprice, ps_supplycost, and c_acctbal/s_acctbal. Non-breaking — Implicit casting handles existing queries. Revenue calculations now return exact decimal results instead of truncated integers. Precision improvement. ✅ Complete
v1.0 2024-05-15 Initial schema creation. All 8 TPC-H tables created with standard column definitions from the TPC-H specification v3.0. Generated at SF=0.01. Baseline — First version of the schema. No migration path (greenfield deployment). ✅ Complete

Migration Process

All breaking schema changes follow a deprecation window:

  1. Announce — Document the planned change in this table with a "Planned" status and target date
  2. Dual-write — Write to both old and new columns/tables simultaneously (minimum 14 days)
  3. Migrate consumers — Update all pipelines, metrics, and queries to use the new schema
  4. Remove — Drop the deprecated column/table after confirming zero reads

Non-breaking changes (additive columns, index creation, type widening) can be applied immediately without a deprecation window.

Rollback Procedures

Each migration includes a rollback script stored alongside the forward migration. For DuckDB-based schemas:

  • Column type changes: ALTER TABLE ... ALTER COLUMN ... SET DATA TYPE (reversible if no precision loss)
  • New columns: ALTER TABLE ... DROP COLUMN
  • Table splits: Restore from pre-migration snapshot (DuckDB EXPORT DATABASE taken before each major migration)
